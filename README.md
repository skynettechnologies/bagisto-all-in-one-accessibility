## Prerequisites

- Bagisto 2.5 or newer
- PHP 8.2 or newer (Bagisto 2.5 itself needs PHP 8.4), with the `curl` and `json` extensions
- Outbound HTTPS from the server to `ada.skynettechnologies.us`, `freeada.skynettechnologies.com` and `skynetaccessibilityscan.com`
- For Bagisto 2.4 or older, use version 1.0.43 of this extension: `composer require skynettechnologies/bagisto-all-in-one-accessibility:1.0.43`

- Tested and verified on Bagisto 2.5.1

## Installation

Run these commands in your Bagisto root folder.

**Step 1:** Install the extension with Composer:

```bash
composer require skynettechnologies/bagisto-all-in-one-accessibility
```

**Step 2:** Create the database table, publish the settings page files and clear the caches:

```bash
php artisan migrate
php artisan vendor:publish --tag=allinoneaccessibility-assets --force
php artisan optimize:clear
php artisan responsecache:clear
```

`responsecache:clear` empties Bagisto's full page cache, so the widget also shows on storefront pages that were cached before the install.

**Step 3:** Open **All in One Accessibility** in the admin menu, right below Dashboard. The first visit registers your store's domain for the free widget.

**Manual installation (without Packagist)**

```bash
git clone https://github.com/skynettechnologies/bagisto-all-in-one-accessibility.git packages/SkynetTechnologies/AllinOneAccessibility
composer config repositories.aioa path packages/SkynetTechnologies/AllinOneAccessibility
composer require "skynettechnologies/bagisto-all-in-one-accessibility:^2.0"
```

Then run Step 2.

**Updating from version 1.x**

1. If you installed 1.x by cloning it into `packages/SkynetTechnologies/AllinOneAccessibility` and adding the `SkynetTechnologies\\AllinOneAccessibility\\` line to the `psr-4` section of your Bagisto `composer.json`, remove that line first (the package now loads its own classes).
2. Run `composer require "skynettechnologies/bagisto-all-in-one-accessibility:^2.0"`, then Step 2.
3. Your widget settings are kept: they are stored at Skynet Technologies for your domain.

**Website domain**

The settings page manages the widget of your store's domain: the hostname of the default channel (**Settings → Channels**), otherwise `APP_URL`. When the admin panel runs on another domain than the store, set the store's domain in `.env`, then run `php artisan config:clear`:

```
AIOA_WEBSITE_DOMAIN=shop.example.com
```

An IP address (for example `127.0.0.1`) is not a valid domain. `localhost` is accepted, but every local install shares Skynet's `localhost` registration, so saving there changes settings other local installs also load.

Package name: `skynettechnologies/bagisto-all-in-one-accessibility`

## CORS Policy Configuration

To avoid CORS policy issues, ensure the following URLs are allowed on your website. Add them to your CORS configuration or trusted domains list.

| **Domain** | **Description** | **Usage** |
| --- | --- | --- |
| https://\*.skynettechnologies.com | Skynet Technologies (Global Domain) | API access and resources |
| https://\*.skynettechnologies.us | Skynet Technologies (US Domain) | API access and resources |
| https://skynetaccessibilityscan.com | SkynetAccessibility Scanner | Accessibility scan results and score |
| https://\*.googleapis.com | Google APIs | Services like Fonts, Translation |
| https://\*.gstatic.com | Fonts APIs | Custom Fonts |
| https://vlibras.gov.br | VLibras – Brazilian Sign Language Service | Sign Language |
| https://ipapi.co | ipapi – IP Geolocation API | Called once during installation to detect an EU location and add the EU-based widget script (endpoint: `/json/`) |

**Instructions**

1. Update your server's CORS configuration to include these URLs.
2. Ensure wildcard subdomains (\*) are supported where necessary.
3. Verify functionality by testing requests to these domains.
4. If issues persist, consult the documentation for CORS configuration guidance.
